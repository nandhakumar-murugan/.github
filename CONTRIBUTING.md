# Contributing Guidelines

Thank you for your interest in contributing to open-source projects maintained by **Nandhakumar Murugan (smnk-infotech / Prema AI Labs)**! 🎉

We welcome contributions of all forms: bug fixes, feature proposals, documentation improvements, unit tests, and performance optimizations.

---

## 🚀 Quick Workflow

1. **Fork the Repository**:
   Click the **Fork** button at the top right of the project repository.

2. **Clone Your Fork**:
   ```bash
   git clone https://github.com/<your-username>/<repo-name>.git
   cd <repo-name>
   ```

3. **Create a Feature Branch**:
   ```bash
   git checkout -b feature/amazing-feature
   # or for bug fixes:
   git checkout -b fix/issue-description
   ```

4. **Make Your Changes**:
   - Follow clean code practices and language-specific conventions.
   - Maintain existing docstrings and write clear, concise commit messages.
   - Add unit tests or verification steps where applicable.

5. **Commit & Push**:
   ```bash
   git add .
   git commit -m "feat: add amazing feature with comprehensive tests"
   git push origin feature/amazing-feature
   ```

6. **Open a Pull Request (PR)**:
   - Provide a clear explanation of what was changed and why.
   - Reference any related open issue (e.g. `Fixes #12`).

---

## 📌 Code Style & Standards

- **Python**: Follow PEP 8 standards (`flake8`, `black`, `ruff`).
- **TypeScript / JavaScript**: Follow ESLint and Prettier formatting standards.
- **Kotlin / Android**: Follow official Kotlin coding conventions & Android Jetpack architectural principles (MVVM / MVI).
- **Documentation**: Ensure all new public functions, classes, and APIs have informative docstrings.
